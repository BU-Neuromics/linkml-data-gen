# LinkML feature support

How each LinkML construct is handled during generation. "Supported" means the
generator produces correct, schema-valid data for that feature; "not enforced"
means the construct is currently ignored (a documented gap, not a silent one).

## Classes

| Feature | Handling |
| --- | --- |
| `tree_root` | Used as the default generation root; its inlined collections become the entity pools. |
| `is_a` | Inherited slots are resolved via `class_induced_slots`. |
| `mixins` | Mixin slots are included via `class_induced_slots`. |
| `abstract` | Never instantiated directly — a concrete descendant is chosen. |
| `mixin` (class) | Treated as non-instantiable, like abstract. |
| `slot_usage` | Per-class slot overrides (narrowed range, required, pattern, etc.) are applied. |
| `attributes` | Inline slot definitions are handled identically to top-level slots. |
| `class_uri`, `exact_mappings` | Read by SchemaView; not needed for instance generation. |
| `unique_keys` | **Not enforced** beyond the `identifier` slot. |
| `rules`, `classification_rules` | **Not enforced.** |

## Slots

| Feature | Handling |
| --- | --- |
| `range` (type) | Scalar generated for the resolved base type. |
| `range` (class) | Inlined object or reference, per `is_inlined`. |
| `range` (enum) | A permissible value, or a synthesized CURIE for dynamic enums. |
| `required` | Always populated. |
| `recommended` | Populated with probability `recommended_prob` (default 0.95). |
| optional | Populated with probability `optional_prob` (default 0.55). |
| `multivalued` | A list is generated; cardinality respects `minimum_cardinality`/`maximum_cardinality`. |
| `identifier` | Minted unique id (honors a `pattern` on the slot). |
| `key` | Treated like an identifier (minted, pooled). |
| `designates_type` | Set to the concrete class name (enables polymorphic round-tripping). |
| `inlined` / `inlined_as_list` | Forces nested-object generation (vs. reference). |
| `pattern` | Value generated to satisfy the regex (via `rstr`). |
| `minimum_value` / `maximum_value` | Numeric bounds respected. |
| `minimum_cardinality` / `maximum_cardinality` | Respected for multivalued slots. |
| `ifabsent` | **Not specifically applied** (a value is generated regardless). |
| `equals_expression`, `string_serialization` | **Not enforced.** |
| boolean slot expressions (`any_of`/`all_of`/`none_of`/`exactly_one_of`) | **Not enforced.** |

Reference (non-inlined) multivalued slots are de-duplicated so the same id isn't
repeated within one list.

## Types

Built-in and derived types are generated by their base:

| Base / type | Output |
| --- | --- |
| `string` | A short realistic phrase, or a slot-name-appropriate value (see below). |
| `integer` | Bounded integer (default `[0, 1000]`). |
| `float` / `double` / `decimal` | Bounded float (default `[0, 1000]`, 3 dp). |
| `boolean` | `true`/`false`. |
| `date` | `YYYY-MM-DD` within a fixed window. |
| `datetime` | RFC3339 with UTC offset (timezone-aware). |
| `uri` / `uriorcurie` / `curie` | A URL or CURIE-shaped string. |
| derived types (`typeof`) | Resolved to their base and generated accordingly. |

### Slot-name heuristics (string ranges)

When a string slot's name contains a known keyword, a matching Faker provider is
used so labels read naturally: `email`, `url`/`uri`/`location`, `phone`,
`first_name`/`last_name`/`full_name`, `username`, `city`, `country`, `state`,
`zip`/`postal`, `address`/`street`, `company`/`organization`/`institution`,
`title`/`label`, `description`/`summary`/`note`, `color`, `version`, `name`,
`id`/`code`/`accession`. Anything else falls back to a short word phrase.

Override any of this per slot with a [hint](hints.md) (`faker:`, `choices:`,
`const:`, `pattern:`, …).

## Enums

| Feature | Handling |
| --- | --- |
| `permissible_values` | A value is chosen uniformly (or by `weights` from a hint). |
| `meaning` on a value | Ignored for generation — the permissible-value *name* is emitted. |
| dynamic enums (`reachable_from`) | A plausible CURIE is synthesized from a declared `source_nodes` prefix, e.g. `UBERON:0002310`. The CURIE is **not** checked against the live ontology. |
| `matches` / expression enums with no usable hint | A placeholder token is emitted. |
| empty/stub enums (no values) | A placeholder token is emitted (valid only if the schema accepts free strings there). |

## Imports

Imports (including `linkml:types` and cross-module imports) are resolved by
SchemaView. The generator loads the schema **unmerged** so each class keeps its
source-module provenance, which powers module-based [scope selection](scope.md).

## Summary of what is *not* enforced

- Cross-slot logic: `rules`, `classification_rules`, boolean slot expressions,
  `equals_expression`, `string_serialization`.
- `unique_keys` beyond the identifier slot.
- `ifabsent` defaults.
- Dynamic-enum membership against the real ontology.
- Referential integrity in `--list` / single-instance mode (container mode *is*
  referentially complete).

For numeric and categorical realism, supply a [hints file](hints.md) — it covers
distributions, weighted categoricals, fixed value sets, and more.
